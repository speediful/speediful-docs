Installation and Setup

Administrator Actions​

These steps require a system administrator with Windows and SQL Server admin rights. The installer prompts for the SQL Server connection and your license key(s), so a standard installation needs three steps: install Speediful, enable xp_cmdshell, and configure resource governance. Granting the BULK INSERT permission is needed only when SQL Server's setup differs from the default.

Install Speediful​

Run the installer and follow the on-screen prompts. After the installation completes, the installer prompts you to configure your SQL Server connection and register your license key(s).

The installer asks which SQL Server instance will run Speediful. It lists each instance on the computer with the account its SQL Server service runs as. Select every instance you will run Speediful's stored procedures on. When the computer has only one instance, it is already selected. The installer grants the selected instances' SQL Server and SQL Server Agent accounts read and write access to Speediful's work, blob, configuration and keys directories, and grants nothing to instances you do not select.

On the installer's final page, the option Open the folder containing the SQL scripts is checked by default. Leave it checked to open the sql folder of the installation directory (by default C:\Program Files\Speediful\SLAM\sql) in File Explorer. That folder holds the scripts you run in SQL Server Management Studio to install the stored procedures. Silent installs do not open the folder.

important

If the installer warns that it "could not give every SQL Server account access to Speediful's directories", grant the access it lists by hand. Follow the steps at Installation Issues.

Enable xp_cmdshell​

Speediful needs xp_cmdshell enabled to run from SQL Server Management Studio. Enabling it means changing an advanced configuration option:

  1. Open SQL Server Management Studio (SSMS) and connect to your SQL Server instance.

  2. Run the following T-SQL commands:

    -- Allow advanced options to be changed
    EXEC sp_configure 'show advanced options', 1;
    RECONFIGURE;

    -- Enable xp_cmdshell
    EXEC sp_configure 'xp_cmdshell', 1;
    RECONFIGURE;

  3. Verify it's enabled by running:

    EXEC sp_configure 'xp_cmdshell';

    The run_value is 1 when it's enabled.

Configure Resource Governance Settings​

important

Set SQL Server's max server memory, or pin Max In-Flight Bytes, while you install. SQL Server's max server memory is unlimited by default, and Speediful then limits itself to 10% of RAM, up to 2GB. Max In-Flight Bytes is the setting that most often limits speed.

Either option gives Speediful a larger memory budget. You can also do both: setting max server memory caps SQL Server, and the pinned value sets Speediful's budget.

  • Option 1: Set SQL Server's max server memory. Speediful then sizes its budget at 75% of the RAM left over, up to 8GB. The setting also caps SQL Server, which needs memory for BULK INSERT, so choose the value with your DBA (see SQL Server out of memory). This example caps SQL Server at 24GB (24576MB):

    EXEC sp_configure 'show advanced options', 1;
    RECONFIGURE;

    EXEC sp_configure 'max server memory (MB)', 24576;
    RECONFIGURE;

  • Option 2: Pin Max In-Flight Bytes with configure_resources. A pinned value is not limited to 8GB. While SQL Server's max server memory is unlimited, SQL Server competes with Speediful for the memory you pin, so pin only what the machine can spare. This example pins it at 8GB:

    (admin powershell prompt)
    PS C:\WINDOWS\system32> cd "C:\Program Files\Speediful\SLAM"
    PS C:\Program Files\Speediful\SLAM> .\speediful_slam.exe configure_resources --max_in_flight_bytes "8GB"

    Speediful then prompts for the other settings. Press Enter at each one to leave it unchanged.

Run configure_resources from a PowerShell prompt running with administrator permissions, or use its Windows Start menu item. Resource Governance covers every setting, how Speediful sizes it, and the command-line parameters.

Grant BULK INSERT Permission​

A default SQL Server installation needs no action here. Speediful writes staged data to SQL Server with BULK INSERT for performance (query results, load results, and other operations that write large tables). BULK INSERT needs the server-level ADMINISTER BULK OPERATIONS permission on the SQL Server login that Speediful connects as.

With Windows Authentication (the default), Speediful connects as the SQL Server service account. SQL Server setup adds that account to the sysadmin server role, which includes this permission.

If you configure Speediful to use SQL Server Authentication (see SQL Server Connection), or the service account has been removed from sysadmin, grant the permission to that login. Unlike most permissions, you cannot grant it to a database user.

Without it, operations fail with a message like:

SQL Server login does not have permission to run BULK INSERT.

To grant it, connect as a sysadmin and run one of the following:

USE master;
GO
GRANT ADMINISTER BULK OPERATIONS TO [your_login_name];
GO

Or add the login to the bulkadmin server role:

ALTER SERVER ROLE [bulkadmin] ADD MEMBER [your_login_name];
GO

Or, in SQL Server Management Studio: Security > Logins > right-click the login > Properties > Server Roles, check bulkadmin, then click OK.

User Actions​

A SQL developer can do the following step.

Install Speediful Database Objects​

The installation includes 3 SQL scripts in the \sql folder of your installation directory (by default C:\Program Files\Speediful\SLAM\sql). Run them in the database you want to use to install Speediful's procedures, tables and default configuration.

The database you install the scripts in is also where Speediful stages load operations and writes Salesforce query results. Keep raw source data from legacy systems in a separate database.

important

Always run these scripts after installing or upgrading Speediful.

  • SLAM_10_procedures.sql
  • SLAM_20_activity_log.sql
  • SLAM_30_mapping_setup.sql

Change Settings After Installation​

The installer configures the SQL Server connection and your license. An administrator can change them afterwards.

Configure SQL Server Connection​

Run configure_server to change the server, ODBC driver, authentication mode or encryption settings. See SQL Server Connection.

Register Your License​

To add license keys after installation, see License Management.
