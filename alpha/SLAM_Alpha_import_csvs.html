SLAM_Alpha_import_csvs

Overview​

Imports all CSV files from a specified folder into SQL Server tables. Each CSV file becomes a separate table, with automatic schema inference and optimized bulk loading. This is useful for batch importing data exports, migrating data from other systems, or loading reference data.

Only files with a .csv extension are imported. The file name determines the table name, and the first row is assumed to be the header for the column names.

Note: This operation requires valid Salesforce credentials for license validation. However, the profiling itself only accesses SQL Server data.

important

Requires SQL Server 2017 or later.

warning

The SQL Server service account must have read access to the specified folder. Do not use folders under user profiles (e.g., C:\Users\...) as the service account typically cannot access them. Use a shared location such as C:\data\csv_files.

Key Features:

  • Automatic Schema Inference: Detects column types (INT, FLOAT, DATETIME, BIT, NVARCHAR) from CSV data
  • Batch Processing: Imports all CSV files in a folder in one operation
  • Flexible Table Naming: Derive table names from filenames with optional suffix
  • Error Recovery: Continues processing all files even if some fail
  • Duplicate Column Handling: Automatically deduplicates column names with a suffix on import (e.g _1, _2 etc.)

Parameters​

ParameterTypeRequiredDefaultDescription
@folderVARCHAR(MAX)YesPath to folder containing CSV files (e.g., 'C:\data\csv_files')
@suffixVARCHAR(128)No''Suffix to append to table names (e.g., '_20260114')
@separatorVARCHAR(10)No','CSV field separator/delimiter
@quotecharVARCHAR(10)No'"'CSV quote character for text fields
@lineterminatorVARCHAR(10)No'\r\n'CSV line terminator (CRLF for Windows). A file whose first line ends in a bare LF is read as LF when you leave this at the default, so Unix-style files need no setting. Pass it as text ('\r\n', '\n') or as a variable holding the characters themselves (CHAR(13) + CHAR(10))
@encodingVARCHAR(50)No'utf-8'CSV file encoding (supports utf-8, latin1, etc.)
@exists_actionVARCHAR(20)NoSLAM_SettingsAction when destination table exists. See Exists Actions

Table Naming​

Tables are automatically named based on the CSV filename (without .csv extension) plus an optional suffix:

  • Account.csv → Account
  • Account.csv + @suffix='_20260114' → Account_20260114
  • Contact Data.csv + @suffix='_load' → Contact Data_load

Exists Actions​

The @exists_action parameter controls behavior when a destination table already exists. If not specified, uses the value from SLAM_Settings.default_exists_action (defaulted to 'drop' during initial setup).

ActionBehavior
dropDrop existing table and create new one (data loss)
renameRename existing table with timestamp suffix (e.g., _20260114_153045)
appendAdd the CSV rows to the existing table and keep the rows already in it. The CSV's columns must match the table exactly. If the table does not exist, Speediful creates it from the CSV, the same as drop
failCheck ALL destination tables before importing. If any table already exists, the entire operation fails and no CSVs are imported
drop-afterLike drop, but keeps the existing table, renamed, until that CSV's import succeeds. See The drop-after option

Usage Examples​

Basic Import​

Import all CSV files from a folder:

EXEC dbo.SLAM_Alpha_import_csvs @folder = 'C:\data\csv_files';

With Table Suffix​

Add a date suffix to all imported tables:

EXEC dbo.SLAM_Alpha_import_csvs
    @folder = 'C:\data\csv_files',
    @suffix = '_20260114';

Alternate Encoding​

Import CSV files with Latin-1 encoding:

EXEC dbo.SLAM_Alpha_import_csvs
    @folder = 'C:\data\csv_files',
    @encoding = 'latin1';

Fail If Tables Exist​

Prevent accidental overwrites by failing if any destination table already exists. All destination tables are checked before any CSVs are imported. If any conflict is found, the entire operation fails immediately:

EXEC dbo.SLAM_Alpha_import_csvs
    @folder = 'C:\data\csv_files',
    @exists_action = 'fail';

Append to Existing Tables​

Append CSV data to existing tables. The CSV schema must exactly match the existing table. If Speediful detects a schema mismatch for a file, it skips that file and continues with the remaining CSV files.

Speediful imports a CSV whose table does not exist yet into a new table, so the first run with 'append' needs no setup:

EXEC dbo.SLAM_Alpha_import_csvs
    @folder = 'C:\data\csv_files',
    @suffix = '_staging',
    @exists_action = 'append';

Schema Inference​

Column types are automatically detected by scanning all CSV data:

CSV DataSQL Server TypeExample
Integer valuesINT42, -100, 0
Decimal valuesFLOAT3.14, -0.5, 1.23e10
Binary integersBITColumns containing only 0 and/or 1
Date/time stringsDATETIME2024-01-15, 2024-01-15 14:30:00
TextNVARCHAR(n)Account Name, 555-1234
Empty columnsNVARCHAR(1)(all NULL values)

Mixed Types: If a column has mixed data types (e.g., some numbers, some text), the column is promoted to the most general type (usually NVARCHAR).

String Lengths: NVARCHAR columns are sized based on the maximum observed string length in the CSV file.

Error Handling​

Processing continues for all CSV files even if individual files fail. After completion, the output reports:

  • Success count: Number of files successfully imported
  • Failed files: List of files that failed to import
  • Total records: Total rows imported across all files

Error Scenarios​

ScenarioCause
Partial failureSome files failed to import (see the Results pane for details)
Table existsAny destination table already exists and @exists_action='fail' (checked eagerly before import)

File not readable by SQL ServerThe SQL Server service account does not have read access to the CSV file

File Open in Excel​

SQL Server cannot read a CSV file while another program holds it open, so a file left open in Excel cannot be imported.

Every CSV file is checked before the import starts. If any file is open in another program, the whole operation stops immediately and no tables are created, dropped or renamed. Your database is left untouched:

Found 3 CSV files to import
ERROR: The import_csvs operation failed
ERROR: 1 CSV file is open in another program and cannot be imported
CSV files in use:
  - Account.csv
Tip: Close the file in Excel (or whichever program has it open), then run the import again. No tables were changed.

Solution: Close the listed files and run the import again.

File Not Readable by SQL Server​

CSV files are read by the SQL Server service account, not by the user running the stored procedure. A folder you can open yourself is not necessarily readable by SQL Server, and the import reports:

  - Account.csv: SQL Server could not read the file - grant the SQL Server service account read access to the folder

Solution: Grant the SQL Server service account read access to the folder, or move the CSV files to a shared folder such as C:\data\csv_files. Folders under C:\Users are usually not readable by SQL Server.

Table Too Wide for SQL Server​

SQL Server refuses to create a table with more than 1,024 columns, or whose columns need more than 8,060 bytes in a row. When a CSV needs such a table, the import of that file fails and says why. The existing table is kept:

Failed to import Account.csv: SQL Server cannot create a table for this file because it would exceed SQL Server's column or row size limit; the existing table was kept
  - Account.csv: SQL Server cannot create a table for this file because it would exceed SQL Server's column or row size limit; the existing table was kept

This can happen when the CSV values need a wider type than the existing table's columns (for example, BIGINT instead of INT) and @exists_action is 'rename' or 'drop'.

Solution: Split the CSV into files with fewer columns, or reduce the width of the columns.

Value or Row Rejected​

When a value in a CSV file cannot be stored in its column, or a row has the wrong number of fields, the import of that file fails. The failure line names the file, the row and the column, and says what is wrong. Speediful never skips the row: none of the file's rows are imported, and a table created for the file is removed. When you append to an existing table, the table keeps the rows it had and gets none from the file.

Row numbers. Rows are counted the way you count them in the file: data row 1 is the first row after the header. The failure line also gives the row number counting the header, which is the row number a spreadsheet shows. A quoted value that spans several lines is still one row, so in a text editor the line number can be higher.

Columns are named by the CSV header, with their position (column 1 is the first field).

Placeholder text such as NULL or N/A​

When Speediful reads a file to choose its column types, text such as NULL, N/A, NA or NaN counts as an empty value, so a column of numbers with some N/A values is created as a number column. SQL Server then reads the text N/A itself and cannot store it in that column. Speediful does not turn the text into NULL for you, because that would change your data.

Solution: For no value, leave the field empty (,,), then run the import again.

Schema Mismatch​

This error is reported only when @exists_action='append' and the table already exists. The CSV schema must exactly match it:

Causes:

  • CSV has different columns than the table
  • CSV columns are in a different order
  • CSV column types don't match table types

Solution:

  • Drop the table first: DROP TABLE dbo.Account_staging
  • Use @exists_action='drop' to automatically drop and recreate
  • Use @exists_action='rename' to preserve old data

Multiple Failures: If multiple CSV files have schema mismatches, all failures are reported after processing completes.

Requirements​

  • License: Requires a valid license and a configured Salesforce connection (for license validation only. No Salesforce data is accessed)
  • CSV Format: Files must have a header row in the first line
  • Final line break: A file does not need a line break after its last row. Your CSV files are never modified. When a file has no final line break, it is imported from a temporary copy in the work directory, which is deleted afterwards. The work directory needs enough free space for a copy of the file
  • File Extension: Only *.csv files are processed (case-insensitive)
